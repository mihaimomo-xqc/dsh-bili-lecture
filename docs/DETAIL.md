# B 站视频讲义 · 使用说明

## 这个插件做什么

给一条 B 站视频链接，自动完成四步：**取元数据 → 拿转录 → 总结成稿 → 排出 Word**。产出是一份中文 `.docx`，类型可选 **讲义 / 摘要 / SOP / 操作流程**。

所有文档的开头都先放一节「视频速览」：

- **这是什么**：哪门课或哪个项目、谁在讲、覆盖什么范围；
- **用来干什么**：看完或拿着它能完成什么；
- **能解决什么问题**：3–5 条具体问题；
- 可选：适合谁看、前置知识。

正文按文档类型变化：

| 类型 | 正文结构 |
|---|---|
| 讲义 | 8–12 节，每节导语 + 定义 / 公式 / 例子 / 易错点，可用对比表与提示框 |
| 摘要 | 结论先行，4–6 节，800–1200 字 |
| SOP | 适用范围、角色、前置准备、操作步骤表（步骤 / 操作 / 预期结果 / 注意事项）、校验清单、异常处理、回滚 |
| 操作流程 | 触发条件、按时间排序的步骤、分支判断表、输入产出、检查点、失败处理 |

## 怎么用

在对话里让 Agent 调用 `bili_lecture`：

> 把 https://www.bilibili.com/video/BV1DE411H7V8?p=4 做成讲义

参数：

- `url`（必填）：链接、BV 号或 av 号，可带 `?p=N`。
- `kind`：`讲义` / `摘要` / `SOP` / `操作流程`，默认 `讲义`。
- `pages`：默认单 P 视频取该 P、多 P 视频取 P1；显式写 `1-3`、`1,3,5`、`all` 可扩展范围。
- `outputDir`：相对工作目录的输出目录，默认 `<工作目录>/<类型>/`。
- `model`：覆盖总结所用模型，默认跟随当前会话模型。

## 输出

- 文件名：`<BV号>-P<分P>-<标题>.docx`，放在输出目录。
- 排版：A4、中文正文字体、深蓝标题、页脚「第 N / M 页」、表格与提示框。
- 文末一段小字说明「机器转录，可能有误，关键数字请对照原视频」。

## 前置条件与配置

- 网络：`api.bilibili.com`、字幕 CDN、音视频 CDN。
- `ffmpeg` 可用。
- Python 环境有 `faster-whisper` 与 `yt-dlp`；默认探测 `<工作目录>/.venv/bin/python`。

插件配置项：`pythonPath`、`ffmpegPath`、`whisperModel`（默认 `large-v3-turbo`）、`whisperThreads`、`cacheDir`。

字幕存在的视频只需几秒到几十秒；没有字幕的视频要走本地语音转写，耗时约为视频时长的 1–2 倍，请耐心等待或先用 `pages` 只处理一个分 P。

## 边界

- 只处理普通投稿视频的分 P；番剧、直播回放、付费课程等需要登录或 DRM 的内容不支持。
- 转录是机器识别，术语与数字可能出错；插件不会在摘要失败时假装成功，而是输出带标注的「转录整理版」。
- 所有文件只写入工作目录（缓存与输出目录）。

## 验证情况

已在 macOS 桌面版 DSH（profile `desktop`）上安装并验证：

- 插件行激活，`bili_lecture` 工具出现在会话工具列表中；
- 用真实 B 站视频（BV1DE411H7V8 第 4 分 P，3 分 20 秒）跑通完整链路：无字幕 → yt-dlp 取音轨 → ffmpeg 转码 → faster-whisper 本地转写 → 模型总结 → 生成 `.docx`；
- 讲义、摘要、SOP、操作流程四种类型各自生成并渲染检查过，均含开头的「视频速览」、分节、表格、提示框、页脚页码；
- 表格行不会跨页拆开，分页标题会重复表头；
- 摘要 JSON 解析失败时会自动重试，仍失败则输出带标注的「转录整理版」，不会伪造总结。

尚未验证：UP 主自带的 CC 字幕路径（本次测试视频没有字幕），以及在 Windows 上的字体与 ffmpeg 探测。
